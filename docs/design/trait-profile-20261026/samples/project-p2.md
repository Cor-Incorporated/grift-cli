# 案件「EC サイトの画面刷新」の要望と記録

案件側が書いた要望（宣言）と、案件側のリポジトリ（storefront）の git の記録を、別の節に分けて並べます。会社や案件の良し悪しは出しません。

## 案件側が書いた要望

- 触る場所: 画面（その人の変更の 3 割以上）、文書
- 確かめ方: E2E テスト（画面から通しで動かすテスト）
- 10 回に 9 回が収まる間隔: 14 日以内
- 共有してほしい記録: git の記録
- 書いていないこと: 変更を出した日の数、変更の間隔の真ん中の値、役割の見せ方

書いていない項目は、要望が無いという意味です。不足として扱いません。

## 案件のリポジトリから見える進め方

2 人が変更を出しているリポジトリです。人ごとの数字は出しません。

### どこを触るか

いちばん多いのは画面で、変更 113 件のうち 57 件です。次いで、文書（23 件）、設定ファイル（11 件）、種類を分けられなかったファイル（11 件）にも触れています。

### どんな間隔で変更を出すか

変更と変更の間隔は、真ん中の値が 1.0 日で、10 回に 9 回は 12.1 日以内でした。180 日の間に、30 日以上空いた間隔はありません。

### どう確かめるか

テストのファイルも一緒に変えた変更が、113 件のうち 33 件あります。テストの種類は E2E テスト（22 件）と、種類を判別できないテスト（11 件）です。直し（fix）の変更 22 件のうち 11 件で、テストも一緒に変えています。

## この記録では見えないこと

- レビューと課題管理の進め方は入っていません。案件側のレビューと課題管理の記録のファイルを渡していないためです。
- サーバー側の処理は、このリポジトリでは 0 件です。別のリポジトリで管理しているかは、この記録からは分かりません。

## 数字の読み方と限界

- 間隔は小さく分けて毎日出せば短くなり、まとめて出せば長くなります。補正はしていません。
- 場所はファイルの置き場所と拡張子の決まりで分けています。中身は読んでいません。
- 2 人のリポジトリの件数は 1 人の候補者の件数と同じ物差しではありません。照らし合わせでは件数どうしを割り算しません。
