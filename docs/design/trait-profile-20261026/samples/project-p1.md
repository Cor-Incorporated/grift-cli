# 案件「決済 API の保守と機能追加」の要望と記録

案件側が書いた要望（宣言）と、案件側のリポジトリ（payments-api）の git の記録を、別の節に分けて並べます。会社や案件の良し悪しは出しません。

## 案件側が書いた要望

- 触る場所: サーバー側の処理、データベースの定義、テスト
- 確かめ方: 単体テスト、結合テスト
- 変更を出した日の数: 180 日のうち 20 日以上
- 変更の間隔の真ん中の値: 7 日以内
- 共有してほしい記録: git の記録、レビューの記録（forge）
- 書いていないこと: 10 回に 9 回が収まる間隔、役割の見せ方

書いていない項目は、要望が無いという意味です。不足として扱いません。

## 案件のリポジトリから見える進め方

3 人が変更を出しているリポジトリです。人ごとの数字は出しません。

### どこを触るか

いちばん多いのはサーバー側の処理で、変更 227 件のうち 133 件です。次いで、文書（20 件）、自動テストと配布の設定（19 件）、データベースの定義（19 件）、種類を分けられなかったファイル（18 件）にも触れています。

### どんな間隔で変更を出すか

間をあまり空けずに出す進め方です。変更と変更の間隔は、真ん中の値が 1.0 日で、10 回に 9 回は 3.1 日以内でした。180 日の間に、30 日以上空いた間隔はありません。

### どう確かめるか

テストのファイルも一緒に変えた変更が、227 件のうち 94 件あります。テストの種類は単体テスト（75 件）と結合テスト（37 件）です。直し（fix）の変更 57 件のうち 38 件で、テストも一緒に変えています。

## この記録では見えないこと

- レビューと課題管理の進め方は入っていません。案件側のレビューと課題管理の記録のファイルを渡していないためです。
- 案件で使っているほかのリポジトリ（画面、実行環境の設定など）があるかは、この記録からは分かりません。

## 数字の読み方と限界

- 変更を出した日の数は小さく分けて毎日出せば増え、まとめて出せば減ります。要望の「20 日以上」は量の線で、照らし合わせではこの線をそのまま使います。補正はしていません。
- 場所はファイルの置き場所と拡張子の決まりで分けています。中身は読んでいません。
- 3 人のリポジトリの件数は 1 人の候補者の件数と同じ物差しではありません。照らし合わせでは件数どうしを割り算しません。
